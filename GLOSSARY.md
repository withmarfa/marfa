# Glossary

The words this repository uses, and the words it does not. One name per thing. A pull request is checked against this file, and a name that is not here is either an ordinary English word or a mistake.

American English throughout, as `AGENTS.md` requires.

Where Marfa has no rule of its own, the API's names and shapes follow Stripe's API conventions. An object in the API document declares its shape unless it is open on purpose, and `packages/server/src/openapi-open-objects.test.ts` lists each one that is, with the reason.

## The words

| Word                 | What it means                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **item**             | One record. The unit everything else hangs off: it has a type, a state, properties, and a time it occurred at. A tier too, except on `system.*` items, where the dimension does not apply.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **type**             | What an item is, named in the namespace grammar, such as `core.note`, `user.recipe` or `<publisher>.<name>`. A type under `app.*`, `user.*` or a publisher root is registered at run time and enforced, and keeps the `version` its registration names; `core.*` and `system.*` are shipped by the platform and immutable, and `marfa.*` is reserved to it.                                                                                                                                                                                                                                                                                                                                                                                                        |
| **edge**             | A directed relationship between two items, named by an **edge type**. Edges carry properties and a version of their own.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **reverse name**     | The name an edge goes by read from its target, which an edge type may declare: `child-of` for `parent-of`. An edge type also says where it is **written at**, the end whose file writes it. Never "inverse".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **tag**              | A free-form label on an item. Flat, unversioned, and searched alongside the item's text. A release is named by a git tag, `v0.0.1`; call that a **release tag**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **property**         | A named value inside an item, governed by its type's schema. Never "field" for the same thing on the wire.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **link**             | The value a row holds in the property its type names as `link_field`: the row's own id at the vendor that writes the type, by which a connector finds the row. One row's within the type, in every state, and kept as a tombstone when the row is purged. A type's own, never a parent's. The word keeps its ordinary sense of a URL, a blob's link or a `[[name]]` in a Markdown body, where the sentence says which.                                                                                                                                                                                                                                                                                                                                             |
| **tombstone**        | What a purge leaves of a row under its type: its link and its natural key `(source, source_id)`, each with `purged_at` and a `settled_at`, the purge time or the later time of the vendor's own change a connector made in carrying the purge out, moved only later. An entry from the vendor naming the key is a new row only if the vendor changed it after `settled_at`. Kept, never swept, until a row holds the key again or the type goes: one small row per purged key. A link change drops the old link's; registering a type clears its identifier's. A trashed row leaves none. Not a trashed row, nor a revoked grant row.                                                                                                                              |
| **extension**        | A namespaced object of metadata attached to an item by something other than the key that wrote the item. Read and written per namespace, and not to be confused with a blob: an extension is JSON.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **blob**             | Bytes stored by content hash, with a size in `size_bytes` and a MIME type. An item references one; it never contains one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **file**             | An item whose type inherits from `core.file` and refers to the blob that holds its bytes. In a folder, a file on disk, which is one item.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **store**            | A place a blob's bytes live: the disk beside the server, or an S3-compatible bucket. A store answers four verbs on a hash, put, get, has and delete, and carries its own identity in a marker it holds, so a fresh folder is a fresh store. The location log records which stores hold which blob. Never "backend".                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **replicate**        | To give a store the copies its policy wants, by copying blobs from a store that has them: the `blob-replicate` housekeeping job does it for blobs, and Litestream does it for the database. Never "mirror".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| **housekeeping**     | The periodic jobs the server runs on itself, from one table and one scheduler, including the trash purge, version thinning, the log cleanups, the sweeps that bound the smaller tables (never the tombstones), blob replication, the blob integrity check, the unreferenced-blob sweep, the enrichment sweep, the webhook retry poll, the inbound delivery sweep and the heartbeat. None bounds what a connector keeps: its agreements go with their rows, and its state document stays until it is cleared. One is "a housekeeping job", never a job alone: a bare job is a queued bulk action.                                                                                                                                                                   |
| **version**          | A monotonic integer on an item or an edge. A write that names the version it read is held to it: where the row has moved on, it merges or is refused (`versions/update-order`). An update must name one; a create, a delete and a purge may leave it out. The number a release tag carries is the **product version**, and the integer the root answers as `contract` is the **contract version**.                                                                                                                                                                                                                                                                                                                                                                 |
| **contract version** | One integer, answered at `GET /` as `contract`, sent on every answer the application gives as `X-Marfa-Contract` and carried as the document's `info.version`. Every version inside Marfa, this one included, stays at 0 until the first public release. Not the product version and not the build.                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **event**            | One entry in the log of what changed, with an `event_type`. Events are read from the stream and delivered to webhooks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **tier**             | Which layer an item sits in. `feed` holds what arrives in volume and as it came, from connectors and capture, under the source's own type, transitory until it is promoted or archived. `library` holds what a person chose to keep, modeled in a core type or a child of one. Not a permission and not a lifecycle. The **namespace tier** (`core`, `system`, `app`, `user`, `marfa`, publisher) is a different axis and is not this word; say "namespace" for it.                                                                                                                                                                                                                                                                                                |
| **promote**          | To make a library item from a feed item: a core-typed copy, modeled by a person or an app, that points back at its origin with a `derived-from` edge. The feed item stays as it came. A connector type must be readable as a core type, by `parent` or `compatible_with`, for this to be possible.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **state**            | Where an item sits in its lifecycle: `active`, `archived`, `trashed`, `revoked`. Lists and searches default to `active`; `state=any` reads every state in one pass. An export is a copy rather than a listing and carries every state but `trashed`. A connector's **state document** is another thing, the JSON object it keeps on the instance under its source; name it in full.                                                                                                                                                                                                                                                                                                                                                                                |
| **slice**            | The declared subset of an instance one device holds: a type list and a tier, and any edge types it holds whole. What a working copy is a copy of.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **working copy**     | A device's local replica of its slice. It is a copy, not a peer: the server is the truth.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **device**           | Something that keeps a working copy of a slice and a queue of writes, through the core: an app built on the Swift package or the Node module, or the `marfa` command. A folder is a device whose face is a directory.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **pin**              | To hold one row in a working copy by id, whatever the slice says of it. A pinned row is read at once, kept current by catch-up and read again by every hydration, and goes once its pin is off and the slice does not take it (where a write to it waits, at an answered move, the next catch-up that touches it or the next hydration), or when it is purged or its create refused.                                                                                                                                                                                                                                                                                                                                                                               |
| **verdict**          | What the server answers a write with. Accepted, merged with changes, refused with reason, conflicted with a copy, blocked awaiting a dependency, dead after retries.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **key**              | An ordinary API credential, minted by direct owner or local authority, or delegated by a credential with `keys.mint` within its own access. Scoped by explicit permissions and maps, and revocable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **credential**       | An API key or an approved app's OAuth access token. Its permissions and maps define its API access. Direct owner sessions and private machine authority are separate forms of authority.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **access token**     | The credential an app the owner signed in to holds, issued by the OAuth provider and limited to what the owner granted. Not a key.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **local authority**  | Authority supplied only by the private Unix socket to a process running under the server's operating-system account. It is not an API key and cannot be asserted through public HTTP.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **setup code**       | A machine-issued proof that authorizes one owner claim. It grants no API access and stops working when setup closes or its generation is replaced.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **working key**      | An ordinary API key used by a client, script or connector. What it can do depends on its permissions, maps and claimed sources.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **owner**            | The person an instance belongs to. One per instance, established by a one-time claim. A password-authenticated browser session grants direct owner authority.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **instance**         | One Marfa: the deployment that holds a dataset, identified by an `instance_id` minted at first boot and shown at the root route, at `/config` and in an archive's manifest. Never a prefix, never a permission, never a column on an item. **"Server" means the software**: the thing that answers HTTP. A sentence about what holds your items takes "instance"; a sentence about what serves them takes "server". A device or client sentence naming the other end of the wire takes "server" too, whatever the verb: "an item on the server" draws the local-versus-remote contrast that is the point of the sentence.                                                                                                                                          |
| **server**           | The software that answers HTTP for an instance. It is the source of truth that every device copies.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **connector**        | Something outside the server that reads or writes on a person's behalf. Connectors never run inside the server.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **inbound webhook**  | A request a sender outside the instance, such as GitHub, makes to tell a connector something changed. The webhooks the instance sends are **outbound webhooks**; "webhook" alone means those.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **webhook endpoint** | An address on the instance that belongs to one connector registration, where a sender posts inbound webhooks without a credential: the address is the credential. Retired, never deleted, while its registration stands.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **delivery**         | One request that arrived at a webhook endpoint, stored as it came until the connector marks it handled, or one event the instance sends to an outbound webhook, across all its attempts. The server never reads, verifies or acts on an inbound delivery; its connector does.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **hold**             | The lock one process of a connector takes on its registration, under a name the process chose, and renews before its `expires_at`, which the registration shows as `hold_expires_at`: only the process holding a live hold writes the connector's state document or agreements, and no other process takes it while it is live. It lapses when the process stops renewing it, because nothing watches it, and the process's next take answers `renewed: false`, telling it to re-read before it writes. As a verb, _hold_ stays ordinary English.                                                                                                                                                                                                                  |
| **agreement**        | A connector's record of what it and its vendor last agreed about one row, kept on the instance under the connector's source beside the row rather than in it: writing one announces nothing and moves neither the row's `updated_at` nor its version, which is why it is not an extension. `waiting` says a change to the row has yet to be carried across.                                                                                                                                                                                                                                                                                                                                                                                                        |
| **folder**           | A directory on a machine bound to a `system.folder`, whose settings every machine bound to it shares and each writes out as one editable file, `.marfa/folder.yaml`: a search that decides what the folder holds, the defaults a new file takes, and include and ignore lists. A device like any other (the same working copy, the same queue, the same verdicts) with a filesystem as its face: a file in it is an item on the server, and an item its search matches is a file in it.                                                                                                                                                                                                                                                                            |
| **placement**        | Where an item's file sits in a folder: its `in-folder` edge to the folder's `system.folder`, whose `path` names the file from the folder's root. It never decides what a folder holds, and it is never written in a file.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **registry**         | The folder registry: one file on a machine listing its folders, each by its directory and the `system.folder` it follows, so each folder can find the others and a file moved or copied between two of them is told apart. It is never a folder's store, and `MARFA_FOLDER_REGISTRY` names another file in its place. The type registry is the server's catalog of types (`types.md`).                                                                                                                                                                                                                                                                                                                                                                             |
| **embed**            | A file an item's body shows inside it, `![](path)` or `![[file]]`: that file item's `attached-to` edge to the item, in a folder's Markdown file and in a body written through a working copy alike. In a folder, the file's `has-attachment` line lists only what the body does not embed, and the embedded file travels with the file showing it and is written where the link says. It names a file where a file answers to it or its extension names a MIME type; anything else, `![[A note]]` say, is an embed of a note, text in the body and neither a link nor an edge.                                                                                                                                                                                     |
| **frontmatter**      | The block of `key: value` lines a Markdown file in a folder opens with between `---` fences. Its `type`, `tier`, `tags`, `state` and `occurred_at` lines are the item's own fields; `marfa_id` and `marfa_version` name the item and the version the file was written from; a line named for an edge type or a reverse name is an edge's, written in the one file at the end the type names and naming its targets as `"[[name]]"` or `"[[<id>]]"`; every other line is a property. The file's body is the property its type's `body_field` names. Never "header".                                                                                                                                                                                                 |
| **core**             | The Rust engine every native client embeds, through UniFFI to Swift and a native module to Node.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **command**          | The `marfa` command: the reference client of an instance. Every published operation is a command under its area (`status`, `metrics`, `items`, `edges`, `edge-types`, `types`, `search`, `metadata`, `extensions`, `blobs`, `keys`, `config`, `export`, `restore`, `webhooks`, `audit`, `events`, `housekeeping`, `connectors`, `owner`, `setup`, `login`), the working copy sits under `device`, and `folders` is a root of its own. `whoami` reads the root as `status` does, and names the credential. Private setup and recovery commands use `--socket`. Three other roots reach no published operation and are commands all the same: `logout` for the keychain, `operations` for the table itself and `docs` for the public docs site. MCP joins them last. |
| **binary**           | The built file of the `marfa` command. In prose about what it does, say **command**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **operation**        | One thing the API does, named by its method and path, such as `GET /items/{id}`, and by its `operationId` in the API document. Never "door".                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |

## Banned

These name things that were removed. None of them belongs in a tracked file, in code, a comment, a description or a document. Naming one in order to remove it is not a use, which is why they appear below and in the notes beside the permissions; the final legacy sweep greps this list and should not flag its own authority.

| Banned                              | Say instead                                                                                                                                                                                         |
| ----------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **integration**                     | **connector**                                                                                                                                                                                       |
| **space**                           | Nothing. There is no noun for the whole; permissions are named by what they permit, and the instance config lives at `/config`.                                                                     |
| **sync**, as a program or product   | **folders**, for the thing that watches a directory; plain synchronization is still an ordinary English word. `last_sync_at` and the `sync` conformance project name the act rather than a product. |
| **cancelled**, the British spelling | **canceled**, and `canceling` for the same reason; `cancellation` is the American spelling too and is untouched.                                                                                    |
| **substrate**                       | Name the thing itself: the store, the queue, the job table.                                                                                                                                         |
| **hosted mode**                     | Nothing. There is one mode. "Self-hosted runner" and a virtual-hosted S3 URL are different words and are fine.                                                                                      |

## Permissions

A permission is named by what it permits, never by a noun for the whole. The mapping is fixed here so the derived names are as settled as the three the vocabulary decided.

| Permission          | What it permits                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `schema.write`      | Removing type and edge type definitions that already exist, and replacing them, only those the credential's type or edge map grants write on. Registering one is separately fenced by `metadata.types:write` and `metadata.edge_types:write`. The one act both permissions open is a type's own evolution through `PUT /types/{id}`: adding an optional field no stored row holds a value under, and changing its label, description, display hints and version. Every other replacement, a field's removal among them, and every deletion takes `schema.write`. |
| `keys.mint`         | Minting keys within the caller's current access. It also permits listing, changing and revoking keys within that access. An app may delegate only what its grant permits.                                                                                                                                                                                                                                                                                                                                                                                        |
| `items.purge`       | Destroying a trashed row irrecoverably, through the single-row operation and the bulk one alike.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `webhooks.manage`   | Reading, registering and removing the outbound subscriptions that send an instance's events out. Reading takes the same permission as registering.                                                                                                                                                                                                                                                                                                                                                                                                               |
| `config.manage`     | Reading and replacing the instance configuration at `/config`: the enforcement levers and the cleanup-job retention overrides. **Not `config.write`**: a caller refused it cannot read the config either.                                                                                                                                                                                                                                                                                                                                                        |
| `audit.read`        | Reading the audit log. There is no `audit.write` beside it: the server writes the log, a caller never does.                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `grants.manage`     | Listing and revoking other apps' access. Deliberately not `keys.mint`: a key is this app's own credential, a grant is another app's, and folding them together would let an app trusted to rotate a key revoke every other app the owner has authorized.                                                                                                                                                                                                                                                                                                         |
| `instance.read`     | Reading detailed health, metrics, housekeeping status, platform drift, blob storage diagnostics and bulk job status. It grants no content read access.                                                                                                                                                                                                                                                                                                                                                                                                           |
| `instance.maintain` | Running housekeeping, resetting platform type definitions and cancelling bulk jobs. It grants no content write access.                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| `connectors.manage` | Reading and administering connector registrations, endpoints and retained state. Runtime reports and state writes still belong to the connector's own key.                                                                                                                                                                                                                                                                                                                                                                                                       |
| `blobs.manage`      | Managing blob bytes and locations across the instance, without granting item content access.                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| `keys.manage`       | Listing and revoking keys across the instance, and changing their metadata or narrowing access. It does not grant unrestricted minting or widening; changing enforcement overrides also requires `config.manage`.                                                                                                                                                                                                                                                                                                                                                |

These twelve permissions name existing operations. They can be granted to ordinary keys and approved OAuth apps. Content maps remain independent, so holding every named permission does not grant item read or write access. No permission grants private machine authority, owner recovery, access to the direct `/owner` endpoint or archive restore.

The twelve permissions use ten reserved roots: `schema`, `keys`, `items`, `webhooks`, `config`, `audit`, `grants`, `instance`, `connectors` and `blobs`.

- Reserving a root refuses every type registration under it, such as `items.purge` or `config.export`.
- `space` stays reserved even though no permission is named for it.
- Registration checks the reserved set, while the scope parser checks the closed set of permission literals. Anything else under a permission root is refused, including `<root>.*:read` as a type grant.

## Time

One rule across the API, with one carve-out that is named rather than implied.

- Every time field is a verb plus `_at`: `occurred_at`, `created_at`, `updated_at`, `expires_at`, `revoked_at`.
- Every range filter is that verb plus `_after` and `_before`, and **both are exclusive**.
- An item's own time is `occurred_at`, filtered by `occurred_after` and `occurred_before`, both exclusive.
- The audit log uses `created_at`, `created_after` and `created_before`.

**`updated_after` is the carve-out, and it is not a bug.** It is the catch-up filter on `GET /items` and `GET /edges`, and it is **inclusive**. Inclusive because `updated_at` ties across a bulk write: a strict comparison drops every row sharing the cursor's instant, silently and unrecoverably, so a caller deduplicates by id instead. **Do not make it exclusive to satisfy the rule above.**

Its sibling `updated_before` closes the same window at the top and is **exclusive**, like every other bound. The asymmetry is the carve-out stated precisely rather than a second exception: a lower bound is a resume point a client hands back, and an upper bound is an end point a caller chooses. Only the resume point can lose rows to a tie.

## Errors

- `unknown_type`: there is no such type. A lookup answer.
- `type_not_permitted`: the type is not one this credential may reach here. A `403`, decided by the namespace and the credential's permission map rather than by the identifier. It consults no registry, so it is not a statement that the type exists. On an operation that looks up the item an id names, it means the credential may read the item's type and not write it, or reaches no type at all, and it is never the answer for an item whose type the credential may not read. The folder operations are the exception: they refuse a key without write on `system.folder` before looking any row up. On the blob operations it refuses a credential reaching no type before the hash is read, and an upload from one that writes no type; a blob it may not read answers `blob_not_found`, as an unknown hash does.
- `item_not_found`: no item this credential may read has this id, or, on the folder operations, no folder: a readable item that is not a `system.folder` answers it there too. An item of a type it may not read answers exactly as one that does not exist, so the answer is not a statement that no such row exists. A key learns its own reach from `GET /keys/current`, and a signed-in app's token from the scope list on its token response, never from a refusal.
- `api_key_not_found`: no key within this credential's reach has this id. A key it could not have minted answers exactly as one that does not exist, as `item_not_found` does for an item it may not read.
- A **malformed** identifier is neither: it never reached a lookup, so it answers the generic `validation_error` with the field named.
- `edge_cycle`: an edge that would close a cycle. A **self-loop** is refused on every edge type; a longer cycle is detected only on the cycle-prone types, `parent-of` and `supersedes`, where the graph is not acyclic by construction.
