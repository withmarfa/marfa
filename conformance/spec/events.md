# Events

`GET /events` is a server-sent event stream of every mutation, resumable by cursor, and outbound webhooks deliver the same events to a URL.

## The stream

1. A subscription with a bearer credential answers `200 text/event-stream`; without one, `401` in the standard envelope. `compliance/events-contract.test.ts › opens with a stream_cursor frame naming the log head`, `› refuses a subscription with no credential`, `compliance/unauthenticated.test.ts › answers 401 unauthorized on each of them`.
2. The first frame is `stream_cursor`, carrying no `id:` and a `cursor` equal to the id of the last event the log holds; a client resuming from it sees what a live subscriber would have. **Once the prologue is over the stream says so**: a `stream_live` frame, carrying no `id:` and a `cursor` at or past the announced head, follows the replay and the live frames held while it ran, and precedes every frame after them; a stream opened with no cursor sends it straight after its announcement. A frame the filter or the credential withholds is not written at all, so the frame that would show the announced head reached can be one a subscriber is never sent; the marker is what tells such a subscriber it has caught up, and its cursor, the furthest position the stream knows, is one it may resume from without being sent again what the replay covered. The cursor is `null` only where no position is known, a head read that outran its budget with nothing to replay. A stream that ends short, on `stream_incomplete` or `catchup_too_old`, never sends it. `compliance/events-contract.test.ts › opens with a stream_cursor frame naming the log head`, `sync/stream-contract.test.ts › announces a cursor a client can resume from`, `sync/stream-contract.test.ts › marks the end of the replay with a cursor a filtered reader can resume from`.
3. `Last-Event-ID` resumes from a cursor, and every retained event after it is replayed. **A cursor is too old only when the event after it is no longer retained: the log's oldest retained id is greater than the cursor plus one.** Then the stream answers a terminal `catchup_too_old` frame carrying `min_retained_id` and `requested`, and closes. A cursor of `0` against a log whose first event is `1` is a client exactly in step, because a cursor names the last event applied and not the first one wanted, and it is every device that hydrated an instance with an empty log. The stale case cannot be arranged over the wire: an event is retired by the retention sweep on the server's clock, and a request can shorten the retention but cannot run the sweep, so it is asserted where a row can be retired, in the server's own `routes/events.test.ts`. **Ids are issued in commit order, and frames are delivered in that order, edge frames beside item frames.** An event's id is assigned by the insert that commits it, under the log's single writer, so no lower id reaches the log after a higher one, and the stream sends nothing ahead of a frame still waiting on the read that decides whether the subscriber may see it. A reader that closes and later resumes from the last id it received therefore sees every event after it exactly once. The one exception is a stored event whose payload the server can no longer read: it is not replayed, and a subscriber connected when it was published receives its live copy after the replay, behind higher ids, because that copy is the one carrier the event has left (`routes/events-replay-dedupe.test.ts`). The order across both kinds is asserted in the server's own `routes/events-live-order.test.ts`, where a purge announces a row's edges before the row, and `routes/events-edge-hold.test.ts`, where frames queue behind an edge frame whose read is still out, on the live path and in the prologue's hold. `sync/replay.test.ts › resolves a type filter through the same subtree the live stream does`, `sync/replay.test.ts › carries a bulk write, so a catch-up after an import is complete`, `compliance/catchup-too-old.test.ts › replays from a cursor of zero when the log begins at one`, `sync/resume.test.ts › a reader that closes at the head and resumes from its last id misses nothing and repeats nothing`.
4. `type` narrows the stream to a type and its subtree, comma-separated up to ten; `*`, an entry outside the identifier grammar and more than ten entries answer `400 validation_error`; `edges=none` withholds edge events while item events still arrive, `edges=all` delivers them, and any other value answers `400`. `compliance/events-contract.test.ts › refuses a wildcard type filter, a type outside the grammar, an unknown edges value and more than ten types`, `› withholds edge events under edges=none and announces them under edges=all`, `sync/replay.test.ts › resolves a type filter through the same subtree the live stream does`, `sync/stream-contract.test.ts › delivers edge events to a stream filtered by item type`.
5. A write is announced after its transaction commits; a write that rolls back announces nothing. `sync/post-commit.test.ts › a write that rolls back announces nothing, while one that commits does`.
6. Writes continue while a subscription is open. `compliance/edge-events.test.ts › accepts writes while an event stream is open`.

## The vocabulary

7. Item events are `item.created`, `item.updated`, `item.deleted`, `item.restored`, `item.purged` and `item.state_changed`, each carrying `type` and `item`; a tag write and an extension write are both `metadata.changed` carrying `item` and `metadata`, whatever the namespace. `sync/identity.test.ts › keeps the id a client mints for an item, on the row and on the event`, `sync/deletions.test.ts › announces a purge, so a client offline across it learns the row is gone`, `compliance/events-contract.test.ts › announces item.restored when a trashed item comes back`, `› announces item.state_changed on a lifecycle transition`, `› announces metadata.changed on a tag write`, `› announces metadata.changed on an extension write under any namespace`.
8. Edge events are `edge.created`, `edge.updated` and `edge.deleted`, each carrying `type` and `edge`. `compliance/edge-events.test.ts › SSE delivers edge.created and edge.deleted`, `compliance/events-contract.test.ts › announces edge.updated when an edge's properties change`, `sync/identity.test.ts › keeps the id a client mints for an edge`.
9. A bulk write reaches the log like a single write. `sync/replay.test.ts › carries a bulk write, so a catch-up after an import is complete`.
10. A repeated create under an id already used, and a repeated request under an `Idempotency-Key`, announce nothing the second time. `sync/acknowledged.test.ts › answers an item repeat with the stored row and announces nothing`, `› answers an edge repeat with the stored row and announces nothing`, `sync/idempotency.test.ts › answers a repeated create with the first result rather than a second row`.
11. `stream_incomplete` exists in the vocabulary with four reasons; none can be provoked over the wire, so it is unasserted (`coverage.md`). `stream_cursor`, `stream_live` and `catchup_too_old` are the stream's own frames beside it, and none of the four carries an `id:` but `catchup_too_old`, whose id is the oldest retained.

## Outbound webhooks

12. `POST /webhooks` with a `url` and `events` from the vocabulary above answers `201` with the subscription and its `secret` in plaintext, once; later reads redact the secret to its last characters. `compliance/webhooks.test.ts › registers a subscription and returns the secret once`.
13. A matching event is delivered to the URL as JSON with `event_type` and the payload, an `X-Marfa-Event-Type` header, and an `X-Marfa-Signature` of the form `t=<unix seconds>,v1=<hex sha256>` where `v1` is the HMAC of `<t>.<raw body>` under the secret; the delivery is recorded at `GET /webhooks/{id}/deliveries` with its status and attempt, newest first, and the log pages by cursor like every list: a page the `limit` cut answers a `next_cursor`, and the walk reaches every attempt once. `compliance/webhooks.test.ts › delivers a matching event to the URL with a verifiable signature`, `› pages its delivery log by cursor, every attempt once`, `compliance/edge-events.test.ts › delivers edge.created and edge.deleted to a webhook with a valid signature`.
14. An event outside the subscription is not delivered. `compliance/webhooks.test.ts › does not deliver an event outside the subscription`.
15. `events: ["*"]` is refused `400 validation_error`, with `details.errors[].path` naming the position of the offending entry rather than the body: `*` is not in the vocabulary either door publishes, and dispatch matches a subscribed name against an event's own literally, so a stored wildcard would be a subscription that could never fire. A named subscription on the same event is delivered to in the same run, which is what holds the refusal to the door rather than to dispatch. `PATCH /webhooks/{id}` refuses it on the same terms and leaves the stored list where it was. `compliance/webhooks.test.ts › refuses a wildcard subscription while a named one on the same event is delivered`, `› refuses a wildcard on the update door, leaving the stored events alone`.
16. `PATCH /webhooks/{id}` changes `url`, `events`, `type_filter` and `active` in place, each reading back; `DELETE` removes the subscription and every door answers `404 webhook_not_found` for it afterwards. `compliance/webhooks.test.ts › updates the url, events, type filter and active flag in place`, `› deletes a subscription and answers 404 for it afterwards`, `› answers 404 for an unknown subscription on every door`.
17. An event name outside the vocabulary, or a body without `url` or `events`, answers `400`; a key without `webhooks.manage` answers `403` on every door; no credential answers `401`. `compliance/webhooks.test.ts › refuses an event name outside the vocabulary`, `› refuses a body with no url or no events`, `› refuses a key without webhooks.manage`, `› refuses every door without a credential`.

## Audit

18. Every write is recorded at `GET /audit` with the acting key, the action, the resource type and id, and details; the listing filters by `action`, `resource_type` and `resource_id`, bounds by `created_after` and `created_before` (both exclusive of the row's own instant, and both refused when they are not an instant), paginates by cursor, needs `audit.read`, refuses a query key it does not declare, and refuses no credential. `compliance/audit.test.ts › records a write with the acting key, the resource and the action`, `› filters by action and resource type with an excluded control`, `› bounds by created_after and created_before, both exclusive`, `› reads a bound at any precision, and refuses one that is not an instant`, `› paginates with a cursor and delivers every row once`, `› refuses an undeclared bound rather than answering the whole trail`, `› refuses a key without audit.read`, `› refuses a request with no credential`, `compliance/edge-events.test.ts › audit log records edge mutations with edge_id in resource_id`.

## Permissions

19. **A subscriber is told about an edge only where the single read would answer it.** Every `edge.created`, `edge.updated` and `edge.deleted` frame is held, per subscriber, to the two permissions `GET /edges/{id}` asks for: read on the edge type, and read on the source item's type (`edges.md` 23). `edges=none` is a subscriber's own parameter and narrows nothing else. A frame failing either is withheld rather than closing the stream, and a replay from a cursor withholds exactly what the live path does, because a stored frame is the same disclosure reached through a catch-up. A source the server can no longer resolve does not refuse the frame. A purge is the one thing that produces one, because it takes its item's edges with it and announces each cascaded `edge.deleted` after the row has gone; the type nobody can resolve is the same for every subscriber, so refusing there would withhold those deletions from the credential that could read the purged item as well as from the one that could not. It is stated rather than asserted, because what it describes is a disclosure the pair cannot close from where it stands. `compliance/edge-events.test.ts › withholds a live edge frame the credential could not read singly`, `› withholds the same frames on a replay from a cursor`.
