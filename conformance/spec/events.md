# Events

`GET /events` is a server-sent event stream of every mutation, resumable by cursor, and outbound webhooks deliver the same events to a URL.

## The stream

1. A subscription with a bearer credential answers `200 text/event-stream`; without one, `401` in the standard envelope, which the document declares with no content (`findings.md` 5). `compliance/events-contract.test.ts › opens with a stream_cursor frame naming the log head`, `› refuses a subscription with no credential`, `compliance/unauthenticated.test.ts › answers 401 unauthorized on each of them`.
2. The first frame is `stream_cursor`, carrying no `id:` and a `cursor` equal to the id of the last event the log holds; a client resuming from it sees what a live subscriber would have. `compliance/events-contract.test.ts › opens with a stream_cursor frame naming the log head`, `sync/stream-contract.test.ts › announces a cursor a client can resume from`.
3. `Last-Event-ID` resumes from a cursor; a cursor older than the log's minimum retained id answers a terminal `catchup_too_old` frame carrying `min_retained_id` and `requested`, and the stream closes. `sync/replay.test.ts › resolves a type filter through the same subtree the live stream does`, `sync/replay.test.ts › carries a bulk write, so a catch-up after an import is complete`, `compliance/catchup-too-old.test.ts › emits catchup_too_old when Last-Event-ID predates min retained id`.
4. `type` narrows the stream to a type and its subtree, comma-separated up to ten; `*`, an entry outside the identifier grammar and more than ten entries answer `400 validation_error`; `edges=none` withholds edge events while item events still arrive, `edges=all` delivers them, and any other value answers `400`. `compliance/events-contract.test.ts › refuses a wildcard type filter, a type outside the grammar, an unknown edges value and more than ten types`, `› withholds edge events under edges=none and announces them under edges=all`, `sync/replay.test.ts › resolves a type filter through the same subtree the live stream does`, `sync/stream-contract.test.ts › delivers edge events to a stream filtered by item type`.
5. A write is announced after its transaction commits; a write that rolls back announces nothing. `sync/post-commit.test.ts › a write that rolls back announces nothing, while one that commits does`.
6. Writes continue while a subscription is open. `compliance/edge-events.test.ts › accepts writes while an event stream is open`.

## The vocabulary

7. Item events are `item.created`, `item.updated`, `item.deleted`, `item.restored`, `item.purged` and `item.state_changed`, each carrying `type` and `item`; a tag write is `metadata.changed` carrying `item` and `metadata`. `sync/identity.test.ts › keeps the id a client mints for an item, on the row and on the event`, `sync/deletions.test.ts › announces a purge, so a client offline across it learns the row is gone`, `compliance/events-contract.test.ts › announces item.restored when a trashed item comes back`, `› announces item.state_changed on a lifecycle transition`, `› announces metadata.changed on a tag write`.
8. Edge events are `edge.created`, `edge.updated` and `edge.deleted`, each carrying `type` and `edge`. `compliance/edge-events.test.ts › SSE delivers edge.created and edge.deleted`, `compliance/events-contract.test.ts › announces edge.updated when an edge's properties change`, `sync/identity.test.ts › keeps the id a client mints for an edge`.
9. A bulk write reaches the log like a single write. `sync/replay.test.ts › carries a bulk write, so a catch-up after an import is complete`.
10. A repeated create under an id already used, and a repeated request under an `Idempotency-Key`, announce nothing the second time. `sync/acknowledged.test.ts › answers an item repeat with the stored row and announces nothing`, `› answers an edge repeat with the stored row and announces nothing`, `sync/idempotency.test.ts › answers a repeated create with the first result rather than a second row`.
11. `stream_incomplete` exists in the vocabulary with four reasons; none can be provoked over the wire, so it is unasserted (`coverage.md`).

## Outbound webhooks

12. `POST /webhooks` with a `url` and `events` from the vocabulary above answers `201` with the subscription and its `secret` in plaintext, once; later reads redact the secret to its last characters. `compliance/webhooks.test.ts › registers a subscription and returns the secret once`.
13. A matching event is delivered to the URL as JSON with `event` and the payload, an `X-Marfa-Event` header, and an `X-Marfa-Signature` of the form `t=<unix seconds>,v1=<hex sha256>` where `v1` is the HMAC of `<t>.<raw body>` under the secret; the delivery is recorded at `GET /webhooks/{id}/deliveries` with its status and attempt. `compliance/webhooks.test.ts › delivers a matching event to the URL with a verifiable signature`, `compliance/edge-events.test.ts › delivers edge.created and edge.deleted to a webhook with a valid signature`.
14. An event outside the subscription is not delivered. `compliance/webhooks.test.ts › does not deliver an event outside the subscription`.
15. `events: ["*"]` is accepted at registration and reads back as sent, and then matches nothing: no event is delivered to it, where the document offers `*` as the whole vocabulary (`findings.md` 12). `compliance/webhooks.test.ts › accepts a wildcard subscription, which then matches nothing`.
16. `PATCH /webhooks/{id}` changes `url`, `events`, `type_filter` and `active` in place, each reading back; `DELETE` removes the subscription and every door answers `404 webhook_not_found` for it afterwards. `compliance/webhooks.test.ts › updates the url, events, type filter and active flag in place`, `› deletes a subscription and answers 404 for it afterwards`, `› answers 404 for an unknown subscription on every door`.
17. An event name outside the vocabulary, or a body without `url` or `events`, answers `400`; a key without `space.webhooks` answers `403` on every door; no credential answers `401`. `compliance/webhooks.test.ts › refuses an event name outside the vocabulary`, `› refuses a body with no url or no events`, `› refuses a key without space.webhooks`, `› refuses every door without a credential`.

## Audit

18. Every write is recorded at `GET /audit` with the acting key, the action, the resource type and id, and details; the listing filters by `action`, `resource_type` and `resource_id`, bounds by `since` and `until` (both inclusive of the row's own instant), paginates by cursor, needs `space.audit_read`, and refuses no credential. `compliance/audit.test.ts › records a write with the acting key, the resource and the action`, `› filters by action and resource type with an excluded control`, `› bounds by since and until, both inclusive of the row's own instant`, `› paginates with a cursor and delivers every row once`, `› refuses a key without space.audit_read`, `› refuses a request with no credential`, `compliance/edge-events.test.ts › audit log records edge mutations with edge_id in resource_id`.
